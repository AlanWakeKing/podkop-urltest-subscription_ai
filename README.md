# Podkop Auto Config Script
Это вспомогательный инструмент для OpenWrt, который добавляет недостающую функциональность работы с подписками в плагин Podkop (sing-box).

По умолчанию Podkop не имеет встроенной системы для автоматической загрузки и обновления ключей из внешних ссылок-подписок. Данный скрипт устраняет это ограничение, превращая статическую конфигурацию в динамическую систему с автоматическим перебором серверов.

## 🚀 Возможности
- 📥 Поддержка RAW ссылок (GitHub и др.)
- 🌐 Парсинг HTML/текстовых страниц с ключами
- 🔗 Поддержка прямых ссылок (vless://, ss://, trojan:// и др.)
- 🔐 Прямые ключи принимаются только с однозначно разрешённым именем профиля
- 📋 Детерминированная выборка серверов до лимита для каждой секции
- 🧹 Очистка и нормализация конфигов
- ❌ Фильтрация невалидных параметров (xhttp, пустой security и т.д.)
- 🛡 Защита от поломки конфига (fallback)
- ⚡ **Автоматическая интеграция с Podkop (URLTest, Cron)**
- 📦 Автоматическая установка Podkop, если он отсутствует
- 🔄 Автообновление `podkop-update`; безопасная миграция штатного или неучтённого `sing-box` на проверенный `podkop-engine` при `--updates-only`

## ⚙️ Инструкция по установке

### ✦ Шаг 1: Установка
Подключитесь по **SSH** к роутеру и выполните команду:
```bash
wget -O /usr/bin/podkop-update https://raw.githubusercontent.com/AlanWakeKing/podkop-urltest-subscription_ai/main/update.sh
chmod +x /usr/bin/podkop-update
```

### ✦ Шаг 2: Первичная настройка
Редактировать `update.sh` не нужно. Запустите встроенный мастер:

```bash
/usr/bin/podkop-update --setup
```

Скрипт задаст вопросы:
- сколько подписок использовать: от 1 до 3
- ссылки на подписки
- агент подписки: `Happ/2.7.0`, `v2rayNG/1.8.5` или `INCY/2.0.9`
- операционная система: можно пропустить
- версия ОС: можно пропустить
- модель устройства: можно пропустить
- интервал автообновления: от 1 до 12 часов

Ответы сохраняются в:
```bash
/etc/podkop-update.conf
```

Если поля ОС/версии/модели пропустить, скрипт сам попробует определить их на OpenWrt.

Если провайдер подписки требует device id в HTTP-заголовке, скрипт сам создаст постоянный `HWID` и сохранит его в `/etc/podkop-hwid`.

`IP адрес`, `Последний доступ` и `Количество обращений` формируются уже на стороне вашего сервиса по самому факту HTTP-запроса.

Если `Podkop` ещё не установлен, `podkop-update` сначала попробует установить его через официальный `install.sh`, а затем продолжит обычную работу.
Вопросы официального установщика Podkop подтверждаются автоматически ответом `yes`.

### Проверка вручную
После настройки запустите скрипт вручную:
```bash
/usr/bin/podkop-update
```
Если всё прошло без ошибок, Podkop будет обновлён.

Проверить версию скрипта:
```bash
/usr/bin/podkop-update --version
```

Проверить, доступно ли обновление скрипта:
```bash
/usr/bin/podkop-update --check-self-update
```

> [!IMPORTANT]
> В админке могут быть ошибки, но Podkop с ними запустится

### ✦ Шаг 3: Автообновление (Cron)
По умолчанию скрипт сам добавляет и поддерживает две cron-задачи:

Если в мастере выбрано `3`, записи будут такими:
```cron
0 */3 * * * /usr/bin/podkop-update >> /var/log/podkop-update.log 2>&1
0 * * * * /usr/bin/podkop-update --updates-only >> /var/log/podkop-update.log 2>&1
```

Что это значит:
- первая задача обновляет подписки по выбранному интервалу;
- вторая задача ежечасно проверяет обновление скрипта и совместимость ядра `sing-box`. Обновление самого `Podkop` отдельно включается через `AUTO_UPDATE_PODKOP=1`.

### Ручное обновление `podkop-engine`

Текущая целевая версия — `1.14.4-r29`; версия закреплена в скрипте, обновление не переключается автоматически на любой новый релиз.

Запустить проверку и обновление вручную можно так:
```sh
/usr/bin/podkop-update --updates-only
```

Этот режим проверяет обновление самого `podkop-update` и целевого `podkop-engine`; обновление `Podkop` выполняется только если включено `AUTO_UPDATE_PODKOP=1`. Если r29 или более новая версия уже установлена, ядро не переустанавливается.

После запуска проверьте состояние:
```sh
opkg status podkop-engine | grep '^Version:'
sing-box version
podkop check_sing_box
```

При запуске из cron вывод сохраняется в `/var/log/podkop-update.log`; при ручном запуске сообщения выводятся в консоль. При ошибке предварительных проверок пакет не переключается; при сбое во время установки скрипт пытается выполнить откат. Требования и ограничения автоматической замены описаны ниже в разделе «Как это работает».

Чтобы изменить настройки позже, просто снова запустите:
```bash
/usr/bin/podkop-update --setup
```

Лог выполнения будет сохраняться в:
`/var/log/podkop-update.log`

## 🧹  Скрипт удаления
Удалить скрипт и задание cron можно одной командой:
```sh
rm -f /usr/bin/podkop-update && \
sed -i '/podkop-update/d' /etc/crontabs/root && \
/etc/init.d/cron restart
```

## 🧠 Как это работает
- Профили подписки маршрутизируются по исходному `remarks` (а не по добавленному `(1)`/`(2)`): `YOUTUBE NO ADS` → `main`, `Germany # 2` / `Poland # 1` / `Germany # 5` → `Gemini`, `Netherlands #N` → `AI`, `AUTO-EU` → `Other`. Неизвестные профили и ссылки без однозначного имени пропускаются. Для обновления требуются непустые списки всех четырёх секций; при ошибке конфиг остаётся неизменным.
- Первая миграция переносит существующие селекторы маршрутизации `main` (включая `community_lists`, `user_domains` и `fully_routed_ips`) в `Other`; `main` получает `youtube` и адрес YouTube Data API, `Gemini` сохраняет `google_ai`. `AI` использует обновляемые `.srs`-списки OpenAI и Anthropic из официального `SagerNet/sing-geosite` (частота обновления задаётся `podkop.settings.update_interval`, на рабочем роутере — ежедневно). Базовые домены OpenAI/Claude также добавляются в `AI.user_domains` без удаления существующих значений.
- `xhttp` присутствует в профилях Happ, но текущий парсер Podkop/sing-box его не принимает. В JSON сохраняется привязка всех четырёх outbound к профилю, однако при генерации рабочих пулов `xhttp` безопасно отбрасывается (обычно остаются 3 на профиль); он не подменяется на TCP. Не считать это поддержкой всех четырёх транспортов.
- Перед изменением UCI сохраняется приватный backup `/etc/podkop-update-backup-*.config` и UCI export; при ошибке записи или запуска сервиса выполняется откат. При неизменном результате перезапуск не производится. Не копируйте backup с ключами в публичный репозиторий.
- `main` включает `www.googleapis.com` для YouTube Data API. Podkop различает домены, но не URL-пути: через эту секцию также пойдут **другие API Google на том же хосте**. Gemini API `generativelanguage.googleapis.com` остаётся в секции `Gemini`.
- В Podkop правила `fully_routed_ips` всех секций формируются до доменных правил; поэтому перенесённый в `Other` IP-адрес источника имеет приоритет над `main`/`Gemini`/`AI`. После применения необходимо проверить сгенерированный sing-box config на конкретной версии роутера; локальная проверка shell-скрипта её не заменяет.
- При локальном тестировании на роутере отключите `AUTO_UPDATE_SCRIPT=0` в `/etc/podkop-update.conf` (либо временно остановите задачу самообновления), иначе cron может переписать ещё не опубликованный скрипт.
- При `--updates-only` штатный пакет `sing-box` на OpenWrt с `opkg` заменяется **только** на проверенный `podkop-engine` версии `1.14.4-r29`. Это закреплённая совместимая сборка, а не автоматическое скачивание любого нового релиза. Перед заменой проверяются архитектура, SHA256 пакета по HTTPS-метаданным релиза GitHub, действующий конфиг и пробное подключение Hysteria2/VLESS. Для штатного `sing-box` требуется точный установленный пакет для отката; для старого `podkop-engine` — проверенный пакет его точной версии с GitHub для отката. Перед заменой сверяются поля пакетных отношений `Depends`, `Pre-Depends`, `Conflicts`, `Breaks`, `Replaces` и `Provides` целевого и rollback-пакетов; при различии миграция отменяется. Проверенный старый `podkop-engine` обновляется до `1.14.4-r29`; целевая и более новая версии сохраняются, а несовпадение версии пакета и бинарника требует ручной проверки. `podkop-engine-full` и `apk` пропускаются без изменений; неизвестные состояния владения блокируются, а неучтённый бинарник скрипт трогает только после проверенной приватной резервной копии. Пустая или нездоровая база `opkg` также блокирует замену. Перед пакетной операцией скрипт проверяет, что Podkop остановлен; после установки сверяет точные версии пакета/бинарника, процесс, порты и конфиг. Для штатного пакета до переключения сохраняется SHA256 текущего бинарника; исходный пакет принимается как неизменённый только при совпадении этого хеша. При сбое старый пакет повторно устанавливается из проверенного IPK даже если его версия в базе ещё выглядит прежней; после переустановки SHA256 живого бинарника сверяется с извлечённым бинарником из этого IPK, и до совпадения Podkop не запускается. Точный rollback-IPK и manifest предварительно сохраняются в `/overlay/podkop-update-sing-box-recovery`; до записи скрипт подтверждает постоянное хранилище: ровно один отдельный writable mount `/overlay` с файловой системой из allowlist (`ext4`, `f2fs`, `jffs2`, `ubifs`); неизвестные типы и `/dev/loop*` sources отклоняются. Writable `ext4` корня `/` без отдельной записи mount `/overlay` не принимается: переживание перезагрузки так подтвердить нельзя. Read-only mounts отклоняются; `/overlay` не должен быть symlink, а `df` должен подтвердить тот же mountpoint. Recovery-каталог должен быть непосредственным потомком `/overlay`. При неудачном откате эта папка остаётся после перезагрузки и блокирует следующий автоматический пакетный запуск до ручного восстановления. Скрипт пытается подтвердить остановку Podkop и пишет критическую ошибку, если это не удаётся; в этом случае **не считайте сервис остановленным**. Временные копии в `/tmp` пропадут после перезагрузки; не перезагружайте устройство, пока не проверены сервис и сохранённый recovery-IPK.

- Если `/usr/bin/sing-box` и `/etc/init.d/sing-box` **не принадлежат пакетам `opkg`**, перед заменой скрипт сохраняет оригинальный бинарник (gzip + SHA256), init-скрипт и конфигурации в приватный каталог `/etc/podkop-update-sing-box-backup` (0700). При сбое установки или проверки восстанавливает сохранённое ядро и запускает Podkop. После успеха каталог сохраняется для ручного восстановления; **не удаляйте его и не публикуйте — в нём есть ключи**. Если каталог уже существует или после резервирования на `/overlay` остаётся меньше 12 МБ, автоматическая замена отменяется. Откат при отключении питания во время установки не автоматический: потребуется доступ к устройству и сохранённый каталог.
- Для автоматической замены нужны `curl`, `jq`, `wget`, `jsonfilter`, доступ к GitHub API, не менее 35 МБ свободного места в `/tmp` после загрузки пакета-кандидата и, при обновлении старого `podkop-engine`, пакета для отката; также нужно свободное место в `/overlay`. Для пакетного `sing-box` нужен также репозиторий пакетов OpenWrt с **точной** версией для отката. Чтобы **отключить** миграцию на конкретном роутере, добавьте `AUTO_UPDATE_SING_BOX=0` в `/etc/podkop-update.conf`. Отсутствие пакета/сети или неуспех пробного подключения отменяет замену, не останавливая рабочий `sing-box`.
- В режиме `--updates-only` проверяет обновление самого `podkop-update` из GitHub
- Если `Podkop` не установлен, пытается сначала установить его через официальный `install.sh`
- В режиме `--updates-only` пытается обновить `Podkop` через официальный `install.sh` из репозитория `itdoginfo/podkop`
- Если официальный способ недоступен, использует fallback через `apk` или `opkg`
- Загружает конфиги из источников
- Извлекает ключи (vless, ss, trojan и др.)
- Нормализует параметры
- Удаляет невалидные (например xhttp)
- Отклоняет прямые ключи без однозначно разрешённого имени профиля
- Детерминированно выбирает до лимита в каждой секции
- Применяет конфиг в Podkop
- Перезапускает Podkop и проверяет, что сервис успешно поднялся
- Доступность серверов затем проверяется встроенным `URLTest` самого Podkop

- Podkop установлен
